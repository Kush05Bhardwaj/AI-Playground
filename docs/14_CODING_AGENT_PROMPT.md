# Coding Agent Prompt: AI Playground

You are implementing AI Playground, a browser-first educational machine-learning lab for Classes 9-12, with a guided mode for younger students. Read all documents in `/docs` before coding and treat them as the product contract. If a requirement conflicts with the implementation environment, explain the conflict and propose a small ADR rather than silently changing the learning design.

## Build objective

Deliver a working MVP in which a student can explore a seeded two-class dataset, add/change labeled points, run actual k-NN, see a decision boundary generated by that predictor, inspect nearest-neighbor explanations, and review honest held-out evaluation metrics.

## Required boundaries

- React + TypeScript.
- Pure algorithm/evaluation modules with no React, DOM, Canvas, or persistence imports.
- All core algorithms run in the browser; no external AI API or login.
- A fixed, seeded train/test split with no overlap.
- Test metrics must be calculated only from the test subset and actual predictions.
- No mock accuracy values, prerecorded boundary animations, arbitrary code execution, or silent test-set reuse.
- If data/model changes, mark results stale until a new run completes.
- Keep class distinction accessible without relying on color.

## Implementation sequence

1. Inspect repo and propose a file plan.
2. Implement validated experiment/point types and seeded synthetic generators.
3. Implement deterministic train/test split with tests proving disjoint partitions.
4. Implement k-NN, stable tie policy, predictions and nearest-neighbor metadata.
5. Implement evaluation functions and confusion matrix with explicit orientation.
6. Build canvas interactions plus an accessible point list/form alternative.
7. Build decision-boundary rendering by calling the predictor on grid points.
8. Add run-state, stale-result handling, reset and reproducible experiments.
9. Add guided activity and model-limitations panel.
10. Add unit, component and browser tests; run lint, typecheck and production build.
11. Update README with setup, supported algorithms, limitations, and actual verification results.

## Quality gates

Test on hand-calculated examples. Never claim a high accuracy score is meaningful without context. Do not add a Python backend, LLM, account system, analytics, upload feature, or leaderboard until the documented MVP is complete and tested. Do not claim tests have passed unless run. Prefer small, reviewable changes and document trade-offs.
